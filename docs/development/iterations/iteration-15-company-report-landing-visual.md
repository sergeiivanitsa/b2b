# Итерация 15 — визуальный первый экран CompanyReport

ID: 15
Slug: company-report-landing-visual

## Цель

Привести первый экран `/` к утверждённому макету, не изменяя работающий
CompanyReport entry flow из итерации 14.

## Визуальные расхождения до начала работ

- Экран использует ClaimsBrand, голубой фон, рамочную hero-карточку и navy CTA
  вместо текстового бренда, белого canvas и оранжевых CTA из макета.
- Навигация, оффер, копирайт и преимущества не совпадают с утверждённой
  структурой; преимущества сейчас представлены сеткой, а не горизонтальной
  линией с четырьмя узлами.
- Карточка проверки слишком компактна и визуально не отделена как большая
  светло-серая правая колонка.
- Пользователь видит техническую подпись `CompanyReport`.

## Scope

- Только первый экран `/`: header, текстовый бренд, навигация, hero,
  преимущества и карточка проверки.
- Два визуальных варианта уже существующей общей формы ИНН без дублирования
  submit, validation, normalization, loading или navigation.
- Scoped CSS и frontend tests для разметки, доступности и существующего
  сценария перехода.
- Проверка desktop 1440 px, tablet 768 px и mobile 390 px без горизонтального
  scroll.

## Вне scope

- API-контракт, router, plain-INN resolver, auth return target и lifecycle
  CompanyReport.
- Claims handoff, backend, миграции, gateway, deployment и конфигурация
  серверов.
- Новые страницы, навигационные destinations, зависимости или редизайн
  остальных экранов.

## UX-спецификация

- Header: текстовый логотип «ВЗЫСКАНИЕ ДЕБИТОРКИ», подпись, центральная
  навигация и компактная доступная форма ИНН с оранжевым CTA.
- Центральная навигация визуально содержит «Как работаем», «Оплата», «Кейсы»
  и «FAQ». В этой итерации это статичные пункты макета: страницы и якорные
  разделы для них отсутствуют и намеренно не создаются. Нельзя подменять их
  ложными ссылками на проверку или Claims.
- Hero: слева утверждённый оффер, поясняющий текст и четыре преимущества;
  справа самостоятельная светло-серая карточка с началом проверки,
  пояснением, основной формой и reassurance text.
- Desktop: две колонки, горизонтальная линия преимуществ. Tablet: управляемое
  перестроение header и двухколоночной hero без сжатия контролов. Mobile:
  последовательный header и hero, вертикальные full-width контролы и
  преимущества.
- Обе формы сохраняют нормализацию пробелов, проверку 10/12 ASCII цифр,
  `aria-live` validation error, Enter и единое блокирование при переходе.

## Контракты и совместимость

`CompanyReportInnForm` сохраняет callback-контракт и всю бизнес-логику.
Страница сохраняет один `inn`, `isNavigating` и защиту от повторного
перехода. API, `/company/{inn}`, canonical URL и auth-логику не меняются.

## Acceptance criteria

1. Первый экран соответствует утверждённой композиции, не показывая
   техническое название `CompanyReport`.
2. Header и hero используют один и тот же state/coordinator формы ИНН.
3. Доступные label, error state, keyboard submit и disabled state сохранены.
4. На 1440, 768 и 390 px нет горизонтальной прокрутки; mobile-форма читаема.
5. Targeted и полный frontend test suite, production build и независимый
   visual/code review проходят без блокеров.

## Review

Fallback visual/code reviewer подтвердил соответствие композиции макету,
общий coordinator форм, отсутствие изменений API/router/lifecycle и
отсутствие horizontal overflow на 1440/768/390 px. Единственное замечание
P1 — trailing whitespace в roadmap, препятствующий `git diff --check`; оно
исправлено до финальной проверки.

# Процесс разработки

Этот процесс обязателен для изменений в коде, схемах данных, контрактах и
документации, которые влияют на работу продукта.

## Роли и артефакты

- Автор формулирует спецификацию, план, реализацию и отчёт о проверках.
- Независимый reviewer не является автором изменения; он проверяет diff,
  контракты и результаты проверок.
- Артефакты изменения: спецификация, утверждённый план итерации, реализация,
  результаты проверок и решение reviewer.

Для новой итерации скопируйте
[`ITERATION_TEMPLATE.md`](ITERATION_TEMPLATE.md) в `context/Разработка 2.0/` и
заполните его до реализации.

## Последовательность

1. **Спецификация.** Зафиксируйте цель, scope, out of scope, входы/выходы,
   инварианты, контракты, риски и неизвестные. Изучите текущую итерацию и
   связанный код.
2. **Plan mode.** Подготовьте решение без изменения кода. План должен
   покрывать совместимость, данные, миграции, ошибки и тесты.
3. **Утверждение.** Начинайте реализацию только после утверждения плана.
4. **Реализация этапами.** Делайте небольшие законченные этапы в утверждённом
   scope. До изменения API, модели или persistence определите путь миграции и
   обратной совместимости.
5. **Тесты.** Запустите все применимые проверки затронутого сервиса и тесты
   нового поведения. Не маскируйте отсутствующие, частичные или ошибочные
   данные значениями по умолчанию.
6. **Независимое review.** Передайте diff и результаты проверок reviewer по
   [`CODE_REVIEW_CHECKLIST.md`](CODE_REVIEW_CHECKLIST.md). Устраните
   блокирующие замечания и повторите затронутые проверки.
7. **Коммит.** Подготовьте итоговый отчёт. Коммит, push и открытие PR возможны
   только после явной команды пользователя.

Если независимый reviewer недоступен, отметьте review как `pending` и не
заявляйте его выполненным. Продолжение до коммита в таком случае требует
явного решения пользователя.

## Матрица проверок

| Изменение | Обязательные проверки |
| --- | --- |
| `product_api` domain/service/router | `python -m pytest services/product_api/tests_unit -q`; при БД-зависимом изменении — `python -m pytest services/product_api/tests -q` с доступным PostgreSQL |
| `gateway_api` | `python -m pytest services/gateway_api/tests -q` |
| `web_ui` | `npm run lint --prefix services/web_ui`, `npm run test --prefix services/web_ui`, `npm run build --prefix services/web_ui` |
| Модель или persistence Product API | unit tests, миграция из `services/product_api` через `alembic -c alembic.ini upgrade head`, проверка существующих данных и upgrade-пути |
| Межсервисный/API-контракт | проверки всех затронутых сторон и сценарий обратной совместимости |

Проверочный CI workflow запускает только `product_api` unit tests. Отдельный
deploy workflow на `main` также собирает `web_ui` и развёртывает сервисы. Для
Python-backend не настроены отдельные lint или type-check команды; не
заявляйте их выполненными.

## Итоговый отчёт

Отчёт содержит:

1. Что сделано и какие поверхности изменены.
2. Какие контракты, миграции или совместимость затронуты.
3. Запущенные команды и результат каждой.
4. Известные ограничения, пропущенные проверки и существующие baseline-падения.
5. Результат независимого review: `approved` или `changes requested` с
   блокирующими замечаниями.

Текущий baseline: Product API unit tests, Gateway tests, UI tests и UI build
проходят; UI lint имеет существующие ошибки и должен сообщаться как
непройденный, пока не будет отдельно согласовано его исправление.

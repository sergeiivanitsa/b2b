# Checklist независимого review

Reviewer отмечает каждый пункт как `да`, `нет` или `не применимо`. Любой ответ
`нет` с риском для продукта является `changes requested` до исправления или
явно утверждённого исключения.

## Требования и scope

- [ ] Изменение соответствует утверждённой спецификации и плану итерации.
- [ ] Достигнуты критерии приёмки.
- [ ] В diff нет незапланированного кода, рефакторинга или форматирования.

## Контракты и совместимость

- [ ] API, схемы, доменные модели и сериализация сохраняют заявленные
      контракты или имеют согласованный путь миграции.
- [ ] UI и backend согласованы по именам полей, статусам и ошибкам.
- [ ] Чтение существующих данных и старые клиенты остаются работоспособными,
      если их несовместимость не была явно утверждена.

## Данные и миграции

- [ ] Миграция append-only, имеет корректный upgrade-путь и не переписывает
      исторические миграции.
- [ ] Существующие данные сохраняются; destructive-операции не добавлены без
      явного разрешения, backup-плана и проверки восстановления.
- [ ] Изменены модели, сериализация и миграция согласованно.
- [ ] Проверены `pending`, `complete`, `partial` и `failed`, когда они
      применимы к изменению.

## Надёжность и детерминированность

- [ ] `missing`, `partial`, `failed` и `not_found` различимы и не заменяются
      выдуманными значениями, нулями или ложным успехом.
- [ ] Неполные/некорректные данные дают безопасный error или warning.
- [ ] Правила и normalizers не имеют скрытой зависимости от сети, текущего
      времени или случайности; порядок результата стабилен.
- [ ] Normalizers не выполняют HTTP/БД-операции и не включают `raw_payload` в
      нормализованную модель.

## Безопасность

- [ ] Секреты, токены, персональные и production raw provider-данные не
      попадают в код, логи, ответы API или документацию. Fixtures с raw
      provider-полями допустимы только в минимальном обезличенном виде и без
      секретов.
- [ ] Проверены авторизация, границы доступа и безопасная обработка ошибок там,
      где изменение их затрагивает.

## Тесты и результат

- [ ] Есть тесты нового поведения, ошибок, неполных данных и обратной
      совместимости.
- [ ] Выполнены все применимые команды из `AGENTS.md` и `WORKFLOW.md`.
- [ ] Непройденные тесты или baseline-падения явно перечислены с причиной;
      несвязанные исправления не добавлены.

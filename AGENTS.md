# Инструкция для агентов

## Контекст

Репозиторий содержит RU `product_api` (FastAPI), изолированный US/EU `gateway_api`
(FastAPI) и React `web_ui`. Продукт включает Claims и развиваемый контур
`CompanyReport`: provider/DataNewton, нормализацию фактов, агрегирование и
persistence.

## Архитектурные инварианты

- Normalizers не выполняют HTTP- или БД-операции, не хранят `raw_payload` и не
  превращают отсутствующие показатели в нули.
- Provider layer изолирован от router, Claims и persistence; `CompanyReport`
  зависит от provider protocol и сохраняет безопасные статусы `complete`,
  `partial` и `failed`.
- Persistence и миграции сохраняют историю, обратную совместимость и
  приватность данных. Миграции добавляются, а не переписывают историю.
- Правила, нормализация и расчёты детерминированы: одинаковые входы дают
  одинаковый результат и порядок элементов.

## Обязательный порядок работы

1. Прочитайте спецификацию, релевантный код и актуальную итерацию из
   `context/Разработка 2.0/`, а также [README](README.md) и релевантную
   документацию.
2. Подготовьте план в plan mode и получите утверждение.
3. Реализуйте только утверждённый scope небольшими проверяемыми этапами.
4. Выполните применимые проверки, проведите независимое review и подготовьте
   итоговый отчёт.
5. Коммит создаётся только после явной команды пользователя.

Не меняйте несвязанный код. Не добавляйте зависимости без объяснения их
необходимости и влияния. Не выполняйте `commit`, `push`, `reset`, удаление
данных или разрушительные операции без явной команды.

## Проверки

Запускайте из корня репозитория, если не указано иное:

```bash
python -m pytest services/product_api/tests_unit -q
python -m pytest services/gateway_api/tests -q
npm run lint --prefix services/web_ui
npm run test --prefix services/web_ui
npm run build --prefix services/web_ui
```

Интеграционные тесты Product API требуют доступного PostgreSQL:

```bash
python -m pytest services/product_api/tests -q
```

Для миграций перейдите в `services/product_api`:

```bash
alembic -c alembic.ini upgrade head
alembic -c alembic.ini revision --autogenerate -m "<описание>"
```

Создавайте миграцию только при намеренном изменении схемы. Не применяйте
миграции к production или неизвестной БД без явного разрешения и плана
сохранности данных.

## Данные, тесты и отчёт

- Для `missing`, `partial`, `failed` и `not_found` сохраняйте различимую
  семантику, не придумывайте значения и возвращайте безопасные warnings/errors.
- Добавляйте или обновляйте тесты изменённого поведения, ошибок,
  обратной совместимости и сценариев неполных данных.
- В итоговом отчёте укажите сделанное, затронутые поверхности, команды и их
  результаты, известные ограничения и результат независимого review. Любая
  непройденная baseline-проверка должна быть названа явно, без несвязанного
  исправления.
